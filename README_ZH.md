# 工程 AI 主控台（Engineering AI Console）

[English](README.md) · [简体中文](README_ZH.md) · [Français](README_FR.md) · [Русский](README_RU.md)

**面向四步工程研发闭环的本地主控台：想清楚、下指令、动手建、严审计。**
没有厂商预设，没有模型白名单，没有遥测。OpenAI 兼容与 Anthropic 兼容接口都是一等公民，
任意模型 ID 都可以手动输入。

---

## 1. 这是什么，以及它服务于哪套闭环

```
        ┌──────────────────────── 云端主控台 ─────────────────────────────┐
        │  Agent 1：工程总参谋长                                          │
        │  直白推理 · 动作胶囊 · 报告蒸馏                                  │
        └───────────────▲──────────────────────────────────────┬─────────┘
                        │  人工复制 / 粘贴缓冲区                │
                        │                                      ▼
        ┌───────────────┴──────────────┐        ┌──────────────────────────────┐
        │ Agent 2：无状态执行员        │        │ Agent 3：对抗式审计员        │
        │ 全新本地窗口，写代码、       │        │ 全新本地窗口，审整套方案，   │
        │ 回报改动与异常               │        │ 只审不改                     │
        └──────────────────────────────┘        └──────────────────────────────┘
```

本控制台确实运行在本机回环地址上，但仍把 1 号位称作**云端 / 纯对话主控**，核心在于它
不挂载你的本地工程目录与终端，从而让顶层推演上下文保持干净、不被源码和日志挤爆；
2 号与 3 号则是本地 Agent，直接挂载本地工程文件夹，并调用本机真实的编译与测试工具链。

Agent 1 就是本主控台。它用工程母语把问题聊清楚，坚持方案小而可审查，并把它变成两段
可直接粘贴的指令：

1. **生成 Agent 2 执行指令**——严格的施工提示词：限定文件范围、禁止臆造抽象、必须列出
   改动清单与异常报告。
2. **生成 Agent 3 审计请求**——非引导式、以证伪为目标的审计提示词：顶层合理性、隐藏假设、
   实时性/并发/物理失效模式、必须做的实验，以及应当砍掉的过度设计。
3. 把施工结果或审计报告粘回来，点 **蒸馏返回报告**，得到一份三点式「红绿灯人话决策单」：
   能否直接收工、真得改什么、哪些找茬该扔掉。

每轮通过全部本地验证门禁后，Agent 2 会把成果记录成模块化的**本地检查点提交**——对人是
随时可回退的锚点，对 Agent 3 是干净的增量 diff。Agent 3 始终只读；在人工确认之前不会
向远端推送任何内容。

复制/粘贴是刻意的设计。那条手动缓冲区就是**人工回路断路器**：只有工程师本人在搬运文本，
AI 无法改写自己的审计记录，也无法悄悄碰硬件。

## 2. 30 秒快速开始

### 方式 A：本地 Python 服务模式（推荐）

要求：**Python 3.9 或更新版本，零第三方依赖，不需要 Node.js。**

- **Windows：** 双击 `start.bat`。
- **Linux / macOS：** 运行 `./start.sh`（或 `python3 server.py`）。
- Windows 下启动器通过 `pythonw.exe` 在后台拉起服务（无常驻黑框），CMD 窗口随即自动关闭；
  `start.sh` 则以 `server.py --auto-exit` 在前台运行。两者都会自动打开浏览器进入本地页面，
  且只绑定回环地址；再次启动会复用已在运行的实例，不会起第二份。
- 关闭全部控制台网页标签约 5 秒后，后台服务自动退出；在缓冲期内按 F5 刷新会自动重连，
  绝不会被误判成关页。需要看终端输出时带上参数（例如 `start.bat --port 18770` 或
  `start.bat --foreground`）即可保留前台可见窗口。
- 如果本机没有合格的 Python 解释器，启动器会改为直接打开静态页；`server.py` 非零退出时
  会保留真实的 Python 报错信息，不会谎称“找不到 Python”。

### 方式 B：纯静态直连模式（零安装）

直接双击 `dist/index.html`，整个控制台就在浏览器里运行：配置存于浏览器本地存储，请求从
页面直连你的接口（受浏览器常规 CORS 规则约束）。该模式仅在页面以本地文件（`file://`）
打开时生效；若用 http(s) 静态服务器托管页面而本地服务不可达，控制台会保持服务端模式并
显示离线提示条，不会悄悄降级。

### 首次配通一条通道（4 步）

打开 **设置 → 通道**，选择 `主通道` 或 `备用通道`，然后：

1. 用两档分段按钮选 **OpenAI 兼容** 或 **Anthropic Messages**。
2. 填入接口地址。输入框下方的**最终请求地址**会随每次输入和协议切换实时重算，是否会自动
   补 `/v1` 一眼可见，不必等第一次请求才发现路径不对。
3. **先粘贴 API Key**，再去探测端点。输入框失焦或关闭设置弹窗时会自动保存，界面只显示
   末 4 位；需要清空时点旁边的 **清空密钥**。
4. 自由输入任意模型 ID——没有列表可选，也没有隐藏默认值——或点 **拉取模型（Fetch models）**
   从端点取回后一键填入；确认后点 **连通性测试（Test connection）**。特殊网关用的原样 URL
   锁定、思考字段、密钥环境变量、自定义 Header、请求超时与远端 PDF 解析全部收在默认折叠的
   **高级设置**里，标题旁的数字徽章会显示当前有多少项高级覆盖正在生效。

默认的 OpenAI 兼容通道是**标准透传**：请求体只有 `model`、`messages` 和 `stream`，未知
自定义网关不会因为多出未请求的厂商私有字段而返回 400。输入框的“深度思考”开关默认只切换
到已配置的思考模型；网关确实需要思考字段时，再到高级设置里选择对应的请求格式。

## 3. 日常核心体验

- **主备通道一键热切换。** 两个槽位共用同一套请求构造、同一条附件管线、同一套安全边界，
  切换不会改变请求的构造方式。
- **纯本地确定性解析，绝不瞎猜。** 源码、配置文件和 GB18030 工控日志按 UTF-8 → GB18030 →
  windows-1252 的顺序本地解码；`.docx` / `.xlsx` / `.pptx` 直接读包内 XML，不经过任何云服务；
  图片以 data URL 内联发送。超过 200 KB 的提取文本会截断为“前 120 KB + 后 60 KB”，
  防止超长日志挤爆上下文。
- **多模态报错自动降级，而不是整轮失败。** 接口以 HTTP 400/415/422 拒绝图片块时，自动剥离
  图片、附上明确的省略说明并以纯文本重试一次；纯图片消息则安全终止并完整恢复草稿。
- **单条消息上下文瘦身与单步回滚。** 任意消息都可以压缩为精简版本而界面保留原文；会话也
  可以回退到任意一步，换一条更干净的分支重试。
- **软/硬分级复位，不是一颗核按钮。** 软复位立即断开本地流（上游连接随该通道的读取超时
  回收），会话、草稿与密钥原样保留；硬复位可先导出纯文本抢救包，再以单事务清空 IndexedDB
  会话并同步清空本地草稿缓存。
- **Solarized 护眼双主题、四档无损字号缩放、标准/宽屏内容宽度与降闪模式。** 界面支持
  英文、简体中文、法文、俄文。

## 4. 技术边界、隐私保护与二次开发参考

### 4.1 隐私与完整的出站请求清单

这个工具的目标是“可审计”，而不是“回传数据”。

- 本地服务**只绑定 `127.0.0.1`**——绝不是 `0.0.0.0`，也不绑定任何局域网网卡。未指定
  `--port` 时，它会用免令牌的 `GET /api/health` 扫描 `18765..18795` 整个端口段：若应答的
  正是本控制台的服务身份，就直接复用那个实例，不再重复监听；否则绑定 `18765`（被无关
  程序占用则依次尝试到 `18795`）。
- 除单实例探活专用的 `GET /api/health` 免 `X-Console-Token` 外（仍强制校验回环 `Host` 与
  同源 `Origin`），其余 `/api/*` 全部强制校验注入页面的进程级令牌，并精确比对同源
  `Origin` 与回环 `Host`。
- 唯一的页面生命周期流量也只在本地：`POST /api/lifecycle` 发往 `127.0.0.1`（挂载时一次心跳、
  之后每 20 秒一次、页面隐藏时发一条 keepalive `leave`），绝不离开本机，并遵循同样的令牌与
  同源校验。只有 `server.py --auto-exit` 会据此动作：关闭全部控制台网页标签约 5 秒后后台
  服务自动退出，缓冲期内刷新页面则继续运行。
- 静态文件只从 `dist/` 读取，解析后强制校验仍在该目录内；目录穿越与 NUL 字节一律拒绝。
- 请求体有硬上限：配置类接口 1 MB，聊天与文件转发 32 MB。缺失或不实的 `Content-Length`
  会被直接拒绝，绝不无界读取。
- API Key 与自定义请求头值隔离存放在数据目录（`--data-dir`，默认 `.console_data/`）的
  `secrets.json`；`settings.json` 永不保存它们。页面只能看到 `hasKey`、末四位掩码和一个
  12 位十六进制单向指纹。POSIX 下密钥文件权限为 `0600`；按名称配置的环境变量优先于落盘密钥。
- 界面**不加载任何外链、外部字体、图标或徽章**，也绝不自动写剪贴板；每一次复制都需要显式点击。
- 出站请求按阶段严格区分，完整清单如下：
  - **添加附件到草稿（点击发送之前）**：源码、日志、配置文件、Office 文档
    （`.docx` / `.xlsx` / `.pptx`）与图片全部在浏览器本地解码、解压或编码，**不产生任何
    网络请求**。唯一例外是通道开启了可选的**远端文档识别接口（Anthropic Files API）**
    （通道配置字段 `enableRemoteFileApi`）：此时添加 `.pdf` 会发送 `POST .../files`，
    移除尚未发送的草稿 PDF 会发送 `DELETE .../files`。
  - **点击发送**：本地提取出的文本（包裹于 `<attached_file>`）、内联图片数据，以及远端
    PDF 的 `file_id`，会作为本轮聊天上下文的一部分，随聊天请求发往当前激活通道的模型端点。
  - **连通性测试** 与通道设置里的**“拉取模型”**按钮：两者各向该通道端点发起一次携带
    当前通道凭据的 `GET .../models` 请求。
  - **开启 Exa 检索**：检索请求发往配置的 Exa 端点。
  - **远端 PDF 上传 / 删除**：仅在 `enableRemoteFileApi` 开启时按上述规则发出。
- 补充两点网络细节：在 `file://` 纯静态直连模式下，浏览器在发起跨源的聊天、模型、Exa 或
  Files 业务请求前，可能会按标准 CORS 机制先行自动发送一条不携带凭据的 `OPTIONS` 预检请求
  （不会带上 API Key 或自定义请求头值，由浏览器生成而非控制台发出）；Exa 联网检索
  （`/api/search/exa`）使用独立的 30 秒有界超时，不受通道自定义流超时参数影响。
- 切换通道地址、协议或密钥后立即上传/删除远端文件时，文件入口会先把 350 ms 防抖队列里的
  最新配置同步落盘，再用这份同步后的配置重新计算远端文件归属指纹：文件绝不会被传到上一个
  网关，远端删除也绝不会发往另一个端点或凭据空间。
- 启动时若发现旧版遗留在 `settings.json` 里的明文自定义请求头，会先迁移进 `secrets.json`，
  并立即把新写入的 `secrets.json` 镜像到 `secrets.json.bak`（清洗后的 `settings.json` 同理
  镜像到自己的 `.bak`）。任一备份替换失败都会置位持久化脏标记并持续报告存储降级，直到一次
  逐字节重同步成功——此后即便主文件损坏重启，也不会复活旧明文或丢失刚迁移的凭据。

### 4.2 主备通道协议交集

两个槽位共用同一套序列化器、同一条附件管线、同一套安全边界，差异有限且明确：

- **文本历史协议中立。** 会话可以从 OpenAI 切到 Anthropic 再切回来，因为每次请求都用同一份
  中立文本历史重新序列化。
- **思考块不回放。** 只有用户文本与助手文本进入下一次请求；界面上显示的思考过程不会带到
  另一种协议。
- **远端 PDF 识别与 DeepSeek 原生联网工具需要 Anthropic 协议。** 远端文件还要求端点提供
  Anthropic Files API；原生联网要求网关明确声明支持 `deepseek_web_search`。“Anthropic 兼容”
  本身不是承诺：没有该声明时，网关可能拒绝请求或直接忽略工具。OpenAI 兼容槽位仍可使用本地
  附件解析与 Exa 检索。
- 思考字段完全按策略选择性注入（关闭、Anthropic 扩展思考、DeepSeek 推理、OpenAI 推理档、
  enable-thinking），默认不注入任何厂商私有字段。默认 OpenAI 兼容通道因此保持标准透传，
  其余策略都是高级设置里的显式覆盖。Anthropic 扩展思考与自定义 temperature 互斥，不会同时发送。

### 4.3 复位、备份与数据规则

- **软复位**立即中止所有本地流并解锁界面，会话、草稿与密钥不受影响；服务端的上游连接在该
  通道读取超时后回收。
- **硬复位**可先导出纯文本抢救包，然后在单个 IndexedDB 读写事务里清空全部会话记录（不删除
  数据库本身，其他已打开的标签页保持可用），同步清空本地草稿缓存并重载页面；配置回到默认
  值，本地已存密钥可以选择保留。
- 若清库这一步失败，页面不会重载：被中断的消息统一收敛为 `stopped`，流锁字典清空，控制台
  绝不会卡在既无停止按钮也无重试入口的“生成中”半死锁状态。
- **JSON 备份导入**在写入前严格校验：文件上限 32 MB、会话与消息数量有界、时间戳范围合理，
  整份备份在单个事务里原子写入。既有会话保留，ID 冲突时自动换新 ID。
- 草稿使用两个互不重叠的命名空间：欢迎页固定 `eac:draft:welcome`，任意会话统一
  `eac:draft:session:` + 会话 ID。删除或清空任何会话，都不可能误伤其他会话或欢迎页草稿。

### 4.4 从源码构建与仓库目录结构

要求：**Node.js `20.19+` 或 `22.12+`**，以及 `pnpm`（也可用 `corepack pnpm` / `npx pnpm`）。

```bash
pnpm install
pnpm type     # TypeScript，0 错误
pnpm lint     # oxlint，0 警告 0 错误
pnpm build    # rspack 构建 + 第三方许可证清单，不产出 source map
pnpm test     # 逻辑、浏览器、服务端安全与隐私四套自检
```

`dist/` 是刻意入库的：只有浏览器的机器可以离线直接运行，只有 Python 的机器可以起本地服务；
最终用户不需要构建工具链。`dist/THIRD_PARTY_LICENSES.txt` 收录全部运行时依赖的许可证原文，
并额外补录已知内嵌声明（KaTeX 的 mhchem 扩展、Cytoscape 的 Thenable 实现），以及一次自动
扫描的结果——凡是被任何包级许可证文件覆盖不到的嵌入式版权声明，都会被一并收录。

```
src/                    React + TypeScript 前端
  services/api/         URL 归一化、双协议序列化、SSE 解析、看门狗
  services/chat/        会话、草稿、上下文瘦身、复位、备份、纯文本导出
  services/config/      通道/界面/提示词配置、确定性清洗、服务端与静态持久化
  services/attachments/ 本地解码、Office XML 提取、截断保护
  components/           顶栏、动作胶囊、输入框、消息、设置、侧栏等界面
  i18n/                 en.ts（基准）、zh.ts、fr.ts、ru.ts
server.py               单文件 Python 3.9+ 本地微服务
start.bat / start.sh    启动器（双击后台无黑框自动退出，带参数时前台可见；start.sh 具备可执行位，索引模式 100755）
scripts/                构建辅助脚本，含第三方许可证清单生成器
tests/                  逻辑、浏览器文档、服务端安全与隐私自检
dist/                   已入库的生产构建产物；不含 source map
```

本地服务是便利代理，信任模型很窄：它信任本机浏览器与本机用户。任何能读 `.console_data/`
的进程都能读到 `secrets.json`；保护一台已被攻陷的主机不在目标范围内。不要把服务端口通过
反向代理或端口转发暴露到外部。
