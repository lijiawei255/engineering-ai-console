# Engineering AI Console

[English](README.md) · [简体中文](README_ZH.md) · [Français](README_FR.md) · [Русский](README_RU.md)

**Локальная мастер-консоль для инженерного цикла из четырёх шагов: продумать, поручить,
построить, проверить.**
Никаких вендорских пресетов, никаких обязательных списков моделей, никакой телеметрии.
Интерфейсы, совместимые с OpenAI и Anthropic, равноправны; любой идентификатор модели можно
ввести вручную.

---

## 1. Что это и для какого цикла создано

```
        ┌──────────────────────── облачная консоль ────────────────────────┐
        │  Агент 1: начальник инженерного штаба                           │
        │  прямое рассуждение · капсулы действий · сводка по отчёту       │
        └───────────────▲──────────────────────────────────────┬───────────┘
                        │  ручной буфер копирования / вставки  │
                        │                                      ▼
        ┌───────────────┴─────────────┐        ┌──────────────────────────────┐
        │ Агент 2: исполнитель без    │        │ Агент 3: состязательный      │
        │ состояния, новое локальное  │        │ аудитор, новое локальное     │
        │ окно, код и отчёт об ошибках│        │ окно, только читает и ищет   │
        └─────────────────────────────┘        │ слабые места                 │
                                                └──────────────────────────────┘
```

Консоль слушает петлевой адрес на вашей машине, но Агент 1 остаётся **облачной ролью /
ролью чистого диалога**, потому что не подключает ни каталог вашего проекта, ни терминал:
так контекст верхнеуровневых рассуждений остаётся чистым и не переполняется исходным кодом
и журналами. Агенты 2 и 3 — локальные: они напрямую подключают папку проекта и вызывают
настоящую цепочку компиляции и тестов на этой машине.

Агент 1 — это данная консоль. Он обсуждает задачу инженерным языком, отбрасывает пустые
отговорки и превращает согласованный план в две готовые к вставке инструкции:

1. **Задание исполнителю (Агент 2)** — строгая инструкция на сборку: ограниченный набор
   файлов, никаких выдуманных абстракций, обязательный список изменений и отчёт об
   исключениях.
2. **Запрос на жёсткий аудит (Агент 3)** — ненавязчивая, нацеленная на опровержение
   инструкция аудита: общая состоятельность, скрытые допущения, режимы отказа реального
   времени / параллелизма / физики, необходимые эксперименты и лишняя переусложнённость.
3. Вставьте результат сборки или отчёт аудита и нажмите **Сводка по отчёту**, чтобы получить
   «светофорный лист решения» из трёх пунктов на человеческом языке: можно ли сдавать, что
   действительно нужно исправить и какие придирки отбросить.

После того как цикл проходит все локальные проверки, Агент 2 фиксирует результат
модульными **локальными контрольными коммитами**: это мгновенные точки отката для человека
и чистые инкрементальные диффы для Агента 3. Агент 3 работает строго в режиме чтения; ничего
не отправляется в удалённый репозиторий до подтверждения человеком.

Копирование и вставка сделаны намеренно. Этот ручной буфер — **человеческий предохранитель
в контуре**: текст переносит только инженер, поэтому ИИ не может переписать собственную
историю аудита или незаметно затронуть оборудование.

## 2. Быстрый старт за тридцать секунд

### Способ A — локальная служба Python (рекомендуется)

Требование: **Python 3.9 или новее, без сторонних пакетов, Node.js не нужен.**

- **Windows:** двойной щелчок по `start.bat`.
- **Linux / macOS:** `./start.sh` (или `python3 server.py`).
- В Windows лаунчер запускает службу в фоне через `pythonw.exe` — без постоянно висящего
  чёрного окна — и сразу закрывает окно CMD; `start.sh` запускает `server.py --auto-exit`
  в терминале. Оба варианта открывают браузер по умолчанию на локальной странице, слушают
  только петлевой адрес, а повторный запуск переиспользует уже работающий экземпляр вместо
  создания второго.
- Закрытие всех вкладок консоли останавливает фоновую службу примерно через 5 секунд;
  обновление страницы (F5) в этом интервале переподключается и никогда не принимается за
  закрытие. С аргументами (например `start.bat --port 18770` или `start.bat --foreground`)
  окно остаётся видимым, чтобы читать вывод терминала.
- Если подходящего интерпретатора Python нет, лаунчер просто открывает статическую страницу.
  Ненулевой код возврата `server.py` оставляет настоящую ошибку Python на экране.

### Способ B — чисто статический прямой режим (без установки)

Дважды щёлкните `dist/index.html`, и консоль целиком работает в браузере. Конфигурация
хранится в локальном хранилище браузера, а запросы уходят со страницы напрямую к вашему
шлюзу (с обычными ограничениями CORS). Режим действует только для страницы, открытой из
локального файла (`file://`); страница по http(s) без локальной службы остаётся в серверном
режиме и показывает баннер «нет связи» вместо тихого переключения.

### Первый канал за четыре шага

Откройте **Настройки → Каналы** и выберите `Основной` или `Резервный`, затем:

1. Выберите протокол двухпозиционным сегментированным переключателем (**Совместимо с OpenAI** /
   **Anthropic Messages**).
2. Вставьте базовый URL. Строка **Итоговый URL запроса** под полем пересчитывается при каждом
   вводе и смене протокола, поэтому видно, добавится ли `/v1` автоматически, ещё до первого
   запроса.
3. Вставьте ключ API **до** проверки эндпоинта. Он сохраняется автоматически при потере фокуса
   полем или закрытии окна настроек, а в интерфейсе остаются только последние четыре символа.
4. Введите любой идентификатор модели — список не навязывается и скрытого значения по
   умолчанию нет — или нажмите **Получить модели (Fetch models)**, чтобы заполнить его с
   эндпоинта, затем нажмите **Проверить соединение (Test connection)**. Всё для особых шлюзов
   (фиксация исходного URL, поля размышления, имя переменной окружения, свои заголовки,
   тайм-аут запроса, удалённый разбор PDF) находится в свёрнутом разделе
   **Дополнительные настройки**, рядом с заголовком которого показано число активных
   переопределений.

**Глубокое размышление** на канале, совместимом с OpenAI, по умолчанию работает как
стандартная передача: запрос содержит только `model`, `messages` и `stream`, поэтому
незнакомый шлюз не ответит 400 из-за не запрошенного вендорского поля. Переключатель лишь
подставляет настроенную модель размышления; если шлюзу нужен особый формат запроса, выберите
его в дополнительных настройках.

## 3. Как это выглядит в повседневной работе

- **Переключение основного и резервного каналов одним щелчком.** Оба слота используют один
  конструктор запросов, один конвейер вложений и одну границу безопасности, поэтому
  переключение никогда не меняет вид запроса.
- **Локальный детерминированный разбор без догадок.** Исходный код, конфигурации и
  промышленные журналы в GB18030 декодируются на месте (UTF-8 → GB18030 → windows-1252);
  `.docx` / `.xlsx` / `.pptx` читаются из внутреннего XML без облачных сервисов; изображения
  передаются inline как data URL. Ограничитель в 200 КБ не даёт огромному журналу заполонить
  контекст (первые 120 КБ + последние 60 КБ).
- **Мультимодальные ошибки деградируют, а не срывают цикл.** Если шлюз отвечает HTTP
  400/415/422 на блоки изображений, изображения снимаются, добавляется явное уведомление о
  пропуске и запрос один раз повторяется как текст. Сообщение только из изображений
  безопасно останавливается и восстанавливает свой черновик.
- **Ужатие контекста по отдельным сообщениям и откат на один шаг.** Любое сообщение можно
  сжать, сохранив исходный текст на экране; беседу можно откатить к любой точке, чтобы
  попробовать более чистую ветку.
- **Двухуровневый сброс вместо одной «ядерной кнопки».** Мягкий сброс сразу обрывает
  локальные потоки (соединение с сервером освобождается по таймауту чтения канала) и
  сохраняет беседы, черновики и ключи. Полный сброс сначала предлагает текстовый спасательный
  экспорт, затем одной транзакцией очищает все сессии IndexedDB и синхронно очищает локальный
  кэш черновиков.
- **Solarized светлая/тёмная тема, четыре масштаба шрифта без потери качества, стандартная и
  широкая ширина содержимого, режим подавления мерцания.** Интерфейс доступен на английском,
  китайском (упрощённом), французском и русском.

## 4. Технические границы, защита приватности и справка для доработки

### 4.1 Приватность и полный перечень исходящих запросов

Инструмент рассчитан на аудируемость, а не на отправку данных «домой».

- Локальная служба слушает **только `127.0.0.1`** — никогда `0.0.0.0`, никогда сетевой
  интерфейс локальной сети. Без `--port` она сканирует весь диапазон `18765..18795` через
  `GET /api/health` без токена: если отвечает идентичность этой консоли, открывается именно
  тот экземпляр, а не создаётся второй. Иначе служба занимает `18765` (или следующий
  свободный порт до `18795`).
- Каждый вызов `/api/*` требует процессный токен `X-Console-Token`, внедрённый в отдаваемый
  HTML, плюс строгую проверку `Origin` на совпадение источника и проверку петлевого `Host`.
  Единственное намеренное исключение — `GET /api/health` (обнаружение единственного
  экземпляра): он принимает запрос без токена, но проверки `Host` и `Origin` остаются.
- Единственный трафик, связанный с жизненным циклом страницы, тоже локальный:
  `POST /api/lifecycle` на `127.0.0.1` (один heartbeat при монтировании, затем каждые
  20 секунд и один keepalive `leave` при закрытии страницы). Он никогда не покидает машину и
  подчиняется тем же проверкам токена и источника. Реагирует на него только
  `server.py --auto-exit`: закрытие всех вкладок консоли останавливает фоновую службу примерно
  через 5 секунд, а обновление страницы в этом интервале продлевает её работу.
- Статические файлы читаются только из `dist/`, с проверкой разрешённого пути и отказом при
  обходе каталогов и NUL-байтах.
- Тела запросов ограничены: 1 МБ для конфигурационных точек, 32 МБ для чата и пересылки
  файлов. Отсутствующий или недостоверный `Content-Length` отклоняется.
- Ключи API и значения пользовательских заголовков хранятся в `secrets.json` в каталоге
  данных (`--data-dir`, по умолчанию `.console_data/`); `settings.json` их никогда не
  содержит. Страница видит только `hasKey`, последние четыре символа и 12-символьный
  шестнадцатеричный односторонний отпечаток. В POSIX файлы секретов имеют права `0600`.
  Переменная окружения, заданная по имени, приоритетнее сохранённого ключа.
- Интерфейс **не загружает внешние ссылки, шрифты, иконки или значки** и никогда не пишет в
  буфер обмена сам; каждое копирование — явный щелчок пользователя.
- Исходящие запросы строго разделены по этапам; полный перечень:
  - **Добавление вложения в черновик (до нажатия «Отправить»).** Исходный код, журналы,
    конфигурация, документы Office (`.docx` / `.xlsx` / `.pptx`) и изображения декодируются,
    распаковываются или кодируются полностью в браузере — **сетевых запросов нет**. Единственное
    исключение — файл `.pdf`, добавленный или удалённый при включённом переключателе канала
    **удалённый разбор документов (Anthropic Files API)** (поле конфигурации канала
    `enableRemoteFileApi`): добавление отправляет `POST .../files`, удаление ещё не отправленного
    PDF черновика — `DELETE .../files`.
  - **Нажатие «Отправить».** Извлечённый локально текст (в обёртке `<attached_file>`), встроенные
    данные изображений и `file_id` удалённого PDF становятся частью контекста текущего раунда и
    уходят с запросом чата на эндпоинт модели активного канала.
  - **Проверка соединения** и кнопка **«Получить модели»** в настройках канала: каждая
    отправляет один запрос `GET .../models` с учётными данными этого канала.
  - **Поиск Exa**, если включён: запросы поиска уходят на настроенный эндпоинт Exa.
  - **Загрузка / удаление удалённого PDF**, только при включённом `enableRemoteFileApi`,
    по правилам выше.
- Список дополняют две сетевые детали. В чисто статическом режиме `file://` браузер перед
  межсайтовым бизнес-запросом (чат, модели, Exa или Files) может сначала автоматически
  отправить предварительный запрос `OPTIONS` без учётных данных по стандартным правилам
  CORS; такой запрос не содержит ни ключа API, ни значения пользовательского заголовка и
  формируется браузером, а не консолью. Поиск Exa (`/api/search/exa`) использует собственный
  ограниченный тайм-аут 30 секунд и не зависит от пользовательского тайм-аута потока канала.
- Если сменить адрес, протокол или ключ канала и сразу загрузить либо удалить удалённый файл,
  точка входа файлового API сначала синхронизирует отложенную на 350 мс запись настроек в
  локальную службу, а затем пересчитывает отпечаток принадлежности файла по этой
  синхронизированной конфигурации: файл никогда не уйдёт на прежний шлюз, а удалённое
  удаление — на другой адрес или в другое пространство учётных данных.
- При запуске старый открытый пользовательский заголовок из `settings.json` переносится в
  `secrets.json`; свежий `secrets.json` сразу зеркалируется в `secrets.json.bak` (а очищенный
  `settings.json` — в свой `.bak`). Если замена любой резервной копии не удалась, консоль
  сохраняет постоянный маркер и сообщает о деградации хранилища, пока не пройдёт точная
  повторная синхронизация. Поэтому последующий сбой не сможет ни вернуть старый открытый
  текст, ни потерять только что перенесённые учётные данные.

### 4.2 Пересечение возможностей основного и резервного каналов

Оба слота проходят через один сериализатор, один конвейер вложений и одну границу
безопасности. Различия ограничены и явны:

- **Текстовая история нейтральна к протоколу.** Беседа может перейти с OpenAI на Anthropic и
  обратно посреди диалога, потому что каждый запрос заново сериализуется из одной и той же
  нейтральной текстовой истории.
- **Блоки рассуждений никогда не воспроизводятся.** В следующий запрос попадают только текст
  пользователя и текст ассистента; трасса размышлений, показанная в интерфейсе, не уходит в
  другой протокол.
- **Удалённый разбор PDF и встроенный веб-поиск DeepSeek требуют протокола Anthropic.**
  Удалённым файлам нужен ещё и шлюз с Anthropic Files API; нативному поиску — шлюз, явно
  заявляющий поддержку `deepseek_web_search`. «Совместимость с Anthropic» сама по себе ничего
  не гарантирует: без такого заявления шлюз может отклонить запрос или проигнорировать
  инструмент. Слоты, совместимые с OpenAI, по-прежнему могут использовать локальный разбор
  вложений и поиск Exa.
- Поля рассуждений включаются только выбранной стратегией (выключено, расширенное
  рассуждение Anthropic, рассуждение DeepSeek, уровень усилий OpenAI, enable-thinking);
  вендорские поля по умолчанию не добавляются. Поэтому совместимый с OpenAI канал по
  умолчанию остаётся в режиме стандартной передачи, а любая другая стратегия — явное
  переопределение в дополнительных настройках. Расширенное рассуждение Anthropic и
  настраиваемая температура взаимоисключающи.

### 4.3 Правила сброса, резервного копирования и данных

- **Мягкий сброс** немедленно прерывает все локальные потоки и разблокирует интерфейс;
  беседы, черновики и ключи не затрагиваются. Соединение с внешним сервером закрывается по
  таймауту чтения канала.
- **Полный сброс** сначала по желанию выгружает текстовый спасательный файл, затем одной
  транзакцией IndexedDB чтения/записи очищает все записи сессий (сама база не удаляется,
  поэтому другие открытые вкладки продолжают работать), синхронно очищает локальный кэш
  черновиков и перезагружает страницу. Конфигурация возвращается к значениям по умолчанию;
  сохранённые локально ключи можно оставить по выбору.
- Если разрушительная фаза завершилась ошибкой, страница не перезагружается: прерванные
  сообщения переводятся в состояние `stopped`, а блокировки потоков очищаются, поэтому
  консоль никогда не зависает в полусостоянии «идёт генерация» без кнопки остановки или
  повтора.
- **Импорт JSON-резервной копии** строго проверяется до любой записи: предел файла 32 МБ,
  ограниченное число сессий и сообщений, правдоподобный диапазон меток времени, атомарная
  запись одной транзакцией. Существующие беседы сохраняются; конфликтующие идентификаторы
  перегенерируются.
- Черновики используют два непересекающихся пространства имён: приветственная страница —
  `eac:draft:welcome`, любая сессия — `eac:draft:session:` + идентификатор сессии. Удаление
  или очистка любой сессии не может затронуть черновик другой сессии или приветственной
  страницы.

### 4.4 Сборка из исходников и структура репозитория

Требования: **Node.js `20.19+` или `22.12+`**, а также `pnpm` (можно `corepack pnpm` /
`npx pnpm`).

```bash
pnpm install
pnpm type     # TypeScript, 0 ошибок
pnpm lint     # oxlint, 0 предупреждений и 0 ошибок
pnpm build    # сборка rspack + пакет сторонних лицензий, без source map
pnpm test     # четыре автопроверки: логика, браузер, безопасность сервера, приватность
```

`dist/` намеренно хранится в репозитории: машине только с браузером достаточно для офлайн-
запуска, машине только с Python — для локальной службы. Конечному пользователю цепочка
сборки не нужна. Пакет `dist/THIRD_PARTY_LICENSES.txt` воспроизводит лицензии всех
исполняемых зависимостей, включая известные встроенные уведомления (расширение mhchem в
KaTeX, реализацию Thenable в Cytoscape) и результат автоматического сканирования встроенных
уведомлений об авторских правах, не покрытых лицензиями пакетов.

```
src/                    фронтенд React + TypeScript
  services/api/         нормализация URL, сериализация двух протоколов, разбор SSE, сторожа
  services/chat/        сессии, черновики, сжатие контекста, сброс, резервные копии, экспорт
  services/config/      настройки каналов/интерфейса/промптов, очистка, сохранение
  services/attachments/ локальное декодирование, извлечение XML Office, ограничение объёма
  components/           верхняя панель, капсулы действий, ввод, сообщения, настройки, панель
  i18n/                 en.ts (эталон), zh.ts, fr.ts, ru.ts
server.py               локальная микрослужба Python 3.9+ в одном файле
start.bat / start.sh    лаунчеры (авто-выход без консоли при двойном щелчке, передний план с аргументами; start.sh исполняемый, режим 100755)
scripts/                вспомогательные скрипты сборки, включая пакет сторонних лицензий
tests/                  автопроверки логики, браузера, безопасности сервера и приватности
dist/                   зафиксированная production-сборка; без source map
```

Локальная служба — удобный прокси с узкой моделью доверия: она доверяет локальному браузеру
и локальному пользователю. Любой процесс, читающий `.console_data/`, может прочитать
`secrets.json`; защита уже скомпрометированной машины не входит в задачу. Не публикуйте порт
службы через обратный прокси или проброс портов.
